## The idea in plain English

Observer lets interested objects subscribe to changes without the publisher knowing their concrete classes. A release event publisher holds listeners; when a report is released, it delivers the event to the current subscribers.

> Subscription lifecycle and delivery semantics define the useful contract; a list of callbacks alone leaves too much unspecified.

## The problem before the pattern

Calling every concrete notification consumer from the release publisher couples it to dashboards, audit views, and other optional behavior. Subscriptions let those consumers join and leave without changing the publisher.

## Practical use cases

1. UI views updating after model changes.
2. In-process release or configuration notifications.
3. Optional audit or metrics listeners.
4. Decoupled reactions to domain events within one process.

## Java walkthrough

### 1. Register listeners

subscribe validates a listener and gives each registration a unique token. Repeated registrations are independent subscriptions.

### 2. Return lifecycle control

Closing the handle removes its token. Closing it twice is safe; try-with-resources scopes the listener lifetime.

### 3. Snapshot recipients

publish copies current listener values before invoking callbacks. Membership changes during delivery apply to the next event.

### 4. Deliver synchronously

Callbacks run in registration order on the publisher thread. The first thrown exception stops later delivery and propagates.

The key collaboration is visible here (imports and surrounding types are in the complete listing):

```java
for (Consumer<String> listener : List.copyOf(listeners.values())) listener.accept(name);
```

## Extension exercise

Change exception handling to attempt every listener and aggregate failures. Write tests proving the chosen delivery guarantee. For asynchronous delivery, define executor ownership, ordering, queue bounds, and shutdown before replacing direct calls with background tasks.

## Verification

ObserverChecks.java verifies: Registration order, unsubscribe and double-close, no-listener publication, changes during snapshot delivery, fail-fast listener exceptions, and null listeners/events.

```bash
cd examples/observer
javac --release 21 ObserverDemo.java ObserverChecks.java
java ObserverChecks
```

Failures throw `AssertionError`; no `-ea` flag is needed. CI also compares the demo’s actual console output against the checked-in `expected.txt`. These checks exercise observable behavior rather than merely counting classes.

## Tradeoffs and implementation limits

| Concern | Design judgment |
| --- | --- |
| Decoupling | Publisher does not know concrete consumers but delivery can be harder to trace. |
| Lifecycle | Unsubscribe reliably to prevent retained listener graphs. |
| Delivery contract | Ordering, exceptions, reentrancy, and thread choice are part of the API. |

This subject is single-threaded and synchronous. It provides no persistence, retry, exactly-once delivery, backpressure, or cross-process messaging. Listeners are strongly retained until removed. Reentrant publication is not blocked and can recurse; define a policy if callbacks can publish again.
